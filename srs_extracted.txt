1.  Introduction  
1.1  Purpose  
PharmaSphere  is  a  web-based  Pharmacy  Management  and  Prescription  Authorization  System  
designed
 
to
 
streamline
 
and
 
digitize
 
core
 
pharmacy
 
operations
 
within
 
a
 
secure,
 
role-based
 
environment.
 
The  primary  purpose  of  the  system  is  to:  
●  Enable  structured  management  of  prescriptions  and  medication  dispensing.  ●  Enforce  controlled  access  to  prescription-required  and  heavy-dose  medications.  ●  Digitally  manage  medication  inventory  and  supplier  contributions.  ●  Facilitate  secure  ordering  and  subscription-based  medication  services  for  customers.  ●  Ensure  that  pharmacists  and  suppliers  operate  under  administrative  approval  and  supervision.  
The  aim  is  to  simulate  a  real-world  pharmacy  workflow  by  integrating  customers,  pharmacists,  and  
administrators
 
into
 
a
 
centralized
 
platform.
 
1.2  Problem  Statement  
Traditional  pharmacy  management  processes  often  rely  on  manual  verification  of  prescriptions,  
disconnected
 
inventory
 
tracking
 
systems,
 
and
 
limited
 
access
 
control
 
mechanisms.
 
These
 
approaches
 
can
 
lead
 
to:
 
●  Unauthorized  purchase  of  controlled  medications.  ●  Inventory  inconsistencies  and  stock  mismanagement.  ●  Inefficient  prescription  validation  workflows.  ●  Lack  of  structured  approval  processes  for  pharmacists  and  suppliers.  ●  Poor  tracking  of  recurring  subscription-based  medication  orders.  
There  is  a  need  for  a  centralized,  role-based  system  that  securely  manages  prescriptions,  inventory,  
and
 
customer
 
orders
 
while
 
enforcing
 
controlled
 
medication
 
policies.

2.  Functional  Requirements  
2.1  User  Registration  and  Authentication  
FR-1:  The  system  shall  allow  users  to  register  as  a  Customer,  Pharmacist,  or  as  Inventory  
manager..
 
FR-2:  The  system  shall  require  users  to  provide  mandatory  registration  information  (name,  
email,
 
password,
 
role
 
selection).
 
FR-3:  The  system  shall  allow  registered  users  to  log  in  using  valid  credentials.  
FR-4:  The  system  shall  prevent  access  if  invalid  login  credentials  are  provided.  
FR-5:  The  system  shall  allow  users  to  reset  their  password  via  email  verification.  
FR-6:  The  system  shall  enforce  Role-Based  Access  Control  (RBAC)  to  restrict  system  
features
 
according
 
to
 
user
 
role.
 
 
2.2  Prescription  Management  
FR-7:  The  system  shall  allow  Customers  to  upload  prescription  documents.  
FR-8:  The  system  shall  associate  uploaded  prescriptions  with  the  respective  Customer  
account.
 
FR-9:  The  system  shall  allow  Pharmacists  to  review  uploaded  prescriptions.  
FR-10:  The  system  shall  allow  Pharmacists  to  approve  or  reject  prescriptions.  
FR-11:  The  system  shall  notify  Customers  of  prescription  approval  or  rejection  status.

===== PAGE 3 =====
2.3  Medication  and  Inventory  Management  
FR-12:  The  system  shall  allow  Inventory  Manager  to  update  medication  stock  quantities.  
FR-13:  The  system  shall  automatically  deduct  medication  stock  upon  successful  order  
placement.
 
FR-14:  The  system  shall  generate  alerts  when  stock  levels  fall  below  a  predefined  threshold.  
FR-15:  The  system  shall  maintain  a  log  of  stock  transactions  (sales  and  restocking).  
2.4  Order  Management  
FR-16:  The  system  shall  allow  Customers  to  add  medications  to  a  shopping  cart.  
FR-17:  The  system  shall  allow  Customers  to  place  one-time  orders.  
FR-18:  The  system  shall  assign  an  order  status  (Pending,  Approved,  Shipped,  Delivered,  
Cancelled).
 
FR-19:  The  system  shall  prevent  order  placement  if  sufficient  stock  is  not  available.  
3.  Non-Functional  Requirements  
3.1  Performance  Requirements  
●  NFR-1:  The  system  shall  respond  to  user  requests  within  3  seconds  under  normal  
load.
 
 ●  NFR-2:  The  system  shall  support  at  least  100  concurrent  users.  
 ●  NFR-3:  Inventory  updates  shall  reflect  in  the  system  in  real-time.  
 
3.2  Security  Requirements  
●  NFR-4:  All  user  passwords  shall  be  stored  using  secure  hashing  algorithms.  
 ●  NFR-5:  The  system  shall  use  HTTPS  protocol  for  secure  communication.  
 ●  NFR-6:  Role-Based  Access  Control  (RBAC)  shall  restrict  unauthorized  access.  
 ●  NFR-7:  Prescription  documents  shall  be  accessible  only  to  the  respective  Customer  
and
 
authorized
 
Pharmacists.

===== PAGE 4 =====
3.3  Usability  Requirements  
●  NFR-8:  The  system  shall  provide  a  user-friendly  dashboard  for  each  role.  
 ●  NFR-9:  The  system  shall  display  error  messages  for  invalid  inputs.  
 ●  NFR-10:  The  system  interface  shall  be  responsive  and  accessible  via  desktop  and  
mobile
 
browsers.
 
 
3.4  Reliability  Requirements  
●  NFR-11:  The  system  shall  maintain  99%  uptime.  
 ●  NFR-12:  The  system  shall  automatically  back  up  data  daily.  
 
3.5  Maintainability  Requirements  
●  NFR-13:  The  system  shall  use  modular  architecture  to  allow  future  feature  
extensions.

5.  Out  of  Scope  
The  following  functionalities  are  outside  the  scope  of  the  PharmaSphere  system:  
1.  The  system  will  not  provide  medical  diagnosis,  treatment  recommendations,  or  
clinical
 
decision
 
support.
 
 2.  The  system  will  not  replace  licensed  healthcare  professionals  or  regulatory  
pharmaceutical
 
authorities.
 
 3.  The  system  will  not  integrate  with  external  hospital,  insurance,  or  government  
healthcare
 
databases.
 
 4.  The  system  will  not  process  real-time  online  payments  or  integrate  with  
banking/payment
 
gateways
 
(if
 
implemented,
 
payments
 
will
 
be
 
simulated).
 
 5.  The  system  will  not  manage  physical  drug  delivery  logistics  or  courier  tracking  
systems.
 
 6.  The  system  will  not  support  international  pharmaceutical  regulations  or  cross-border  
medicine
 
distribution.
 
 7.  The  system  will  not  include  AI-based  prescription  analysis  or  fraud  detection  
mechanisms.
 
 8.  The  system  will  not  function  as  a  real-world  legally  certified  pharmacy  platform;  it  is  
an
 
academic
 
simulation.

7.  Assumptions,  Constraints  and  Dependencies  
7.1  Assumptions  
1.  All  users  (Customers,  Pharmacists,  and  Inventory  Manager)  have  reliable  internet  
access.
 
 2.  Users  provide  accurate  and  valid  registration  information.  
 3.  Uploaded  prescriptions  are  authentic  documents  issued  by  licensed  medical  
practitioners.
 
 4.  Users  possess  basic  digital  literacy  to  navigate  a  web-based  system.  
 5.  The  system  will  be  deployed  in  a  controlled  academic  or  simulated  environment.  
7.2  Constraints  
1.  The  system  will  be  developed  within  a  limited  academic  semester  timeline.  
 2.  The  system  will  be  web-based  only  and  will  not  include  a  dedicated  mobile  
application.
 
 3.  Budget  limitations  restrict  integration  with  external  APIs  such  as  real  payment  
gateways
 
or
 
national
 
healthcare
 
databases.
 
 4.  The  system  will  use  a  single  centralized  database.  
 5.  Security  measures  will  follow  standard  web  security  practices  but  will  not  meet  
enterprise-level
 
regulatory
 
compliance
 
standards.
 
 
7.3  Dependencies  
1.  The  system  depends  on  database  server  availability  for  storing  user,  prescription,  
inventory,
 
and
 
order
 
data.

 3.  The  system  depends  on  secure  hosting  infrastructure  that  supports  HTTPS  protocol.  
 4.  The  system  depends  on  proper  user  role  configuration  to  enforce  Role-Based  Access  
Control
 
(RBAC).
